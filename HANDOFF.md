### Фото поставщика до API — разрешено заказчиком 23.09.2026

Заказчик как дилер Росхолода разрешил брать фото с сайта, пока не выдан ключ API. Сделано: `supplier:photos` (ТЗ §6, п. 9) — адаптер `RosholodSitePhotoSource` читает `/api/v1/prices/` (там же GUID, характеристики и габариты — пока не берём), задачи по странице в очереди `imports`. С API заменить адаптер в привязке `SupplierPhotoSourceInterface` в `AppServiceProvider`.

На тестовом сайте загрузка запущена 23.09.2026 (`supplier:photos`): 718 страниц по 20 товаров. Сначала шло около 45 секунд на страницу, после обеда — 15–20 секунд. В 17:01 фото было у 8 278 товаров из 15 026 (в 15:06 — у 3 474, в 16:27 — у 6 886), упавших задач нет; загрузка закончится вечером 23.09. Фото есть не у всех товаров на сайте Росхолода, так что итог будет меньше 15 026. Выкладка очередь не рвёт: `queue-imports` дожидается конца текущей страницы (`stop_grace_period` 3600 с), новый контейнер берёт следующую. Проверить: `docker/dc logs --tail 5 queue-imports`. Если очередь оборвалась — продолжить со страницы N: `docker/dc exec app php artisan supplier:photos --page=N`. Характеристики и габариты из того же списка пока не берём — с ними заработали бы фильтры и сравнение, решение за заказчиком.

Лимит отсрочки и блокировка способа оплаты при просрочке, уровни дилерских скидок с прогрессом, счета и закрывающие в кабинете, шаблоны закупки, сотрудники и доступы, вход по SMS, подстановка реквизитов по ИНН.

## 5. Принятые решения, которые важно не сломать

**Импорт**
- Ключ товара — GUID поставщика (`products.external_id`), а не артикул: артикул пуст у 22% карточек и повторяется.
- Применение одной транзакцией; пробный прогон — та же транзакция с откатом.
- Отсутствие товара в снимке считается счётчиком `missing_runs`, а не сравнением времени; снятие — после 3 полных снимков.
- Остатки полного снимка переписываются целиком. Наличие — одним SQL-запросом; «снят с производства» он не трогает.
- Каждое поле товара заполняет один активный профиль (`OwnedFieldsGuard`).
- Импорт не пишет в поля из `locked_fields` (включая `retail_price` и `unit`), не меняет `slug`, витринные категории и ручные фото.
- Неизменившийся файл определяется ещё и по хешу (`import_runs.file_hash`); `ETag` сохраняется только после успешного прогона.
- Существующие склад и бренд с тем же названием связываются, а не создаются заново.

**Каталог и админка**
- Ручные правки — только через `SaveProductByManager` (замки, строка поиска, счётчики категорий, кэш). «Вернуть значение поставщика» снимает замок и обнуляет `source_hash`.
- Товары вручную не создаются; удаляет их мягко только администратор. Категории и бренды удаляет администратор. Импорт запускает менеджер, настройки профиля и поставщика — администратор.
- Кэш каталога сбрасывают `CatalogCacheObserver` (категории, бренды, склады) и действия менеджера; товары наблюдателем не охвачены сознательно. В кэше: навигация (`navigation`), плитки главной (`home`), список брендов (`brands`).
- Смена `slug` ставит 301 без цепочек; новая страница освобождает свой адрес от старого редиректа.
- **Слушатели событий** из `app/Listeners` Laravel находит сам. В `AppServiceProvider` их не регистрировать — иначе они вызываются дважды.

**Витрина**
- На витрине только видимые, не снятые товары из включённых категорий (`CatalogQuery::listed`); выключенная категория скрывает свою ветку. После первого импорта витрина пуста, пока менеджер не включит категории.
- Все выборки витрины — через `CatalogQuery` и `ProductSearch`; цены — через `PriceResolver::forMany` в контроллере или компоненте, шаблоны только показывают.
- Дизайн — из макетов `docs/design`; токены только в `@theme` файла `resources/css/app.css`; разметка собирается из компонентов, между страницами не копируется. Новый компонент добавляется и в стайлгайд.
- Витрина работает без JS обычными ссылками и формами; Livewire и `resources/js/storefront.js` — улучшение поверх.
- Деньги — только целые копейки (`Money`), проценты — базисные пункты (`Percent`); цены выводятся через `Typography::money` с неразрывными пробелами.
- Контейнер — утилита `container-page`: до 1296 px контента, поля 12 · 24 · 32 · 56. Липкие колонки — `top-21` (шапка 68 + 16).
- Каркас получает данные только через `StorefrontLayoutComposer` → `$shell` (`App\View\StorefrontShell`): настройки одним запросом, корневые разделы из кэша каталога, число моделей в сравнении. Ссылки на служебные страницы — только на включённые.
- **Листинги** (`CategoryListing`, `SearchListing`, `BrandListing`) делят состояние через трейты: `FiltersListing` (фильтры, сортировка, страницы в адресе), `RefinesBySection` (раздел `category=` для поиска и бренда), `ChoosesView` (плитка/список в cookie). Общая разметка — компоненты `filter-panel`, `filter-bar`, `filter-chips`, `product-grid`, `section-links`, `pagination`, `empty-results`. Имена полей в адресе совпадают с GET-формой: `price_from`, `price_to`, `in_stock`, `brand[]`, `sort`, `page`, `view`, `q`, `category`.
- **Поиск:** `ProductSearch::scope()` делает `LIKE` по `search_text` один раз и отдаёт id; счётчики и фасеты считаются по этим id. Точное совпадение сравнивает сжатые `sku`, `supplier_code` и `model`, а не `search_text` (иначе артикул в названии другого товара дал бы ложное совпадение).
- **Карточка товара:** строки фактов — `App\View\ProductFacts` (типографика данных §9); вкладки с 768 px и аккордеоны ниже — одна разметка, неактивный раздел помечен `data-inactive`, прячет его CSS вне слоёв; без скриптов разделы идут подряд.
- **Сравнение:** `CompareList` — гость в сессии, клиент в `compare_items`, при входе списки объединяются (`MergeGuestComparison`), не больше 4. Кнопка `x-compare.toggle` рисует обе формы (добавить и убрать — один адрес, разные методы), скрипт отправляет форму с `Accept: application/json` и переключает `hidden`. Таблица — `App\View\ComparisonTable`: «Критично для монтажа» (габариты, масса, главные характеристики) первым блоком, совпадающие строки — сноской.
- **Уведомления** об итоге действия — `x-ui.notice`: без скриптов из сессии (`notice` = `text`, `href`, `link`), со скриптами — из `<template data-notice-template>` каркаса.
- **Адреса без маршрута:** любая 404 сначала спрашивает `redirects` (`FollowRedirect` в `bootstrap/app.php`), затем `Route::fallback` открывает включённую страницу по slug, затем 404 в каркасе витрины. Текст страниц — Markdown через `App\View\RichText` (HTML вырезается). Ошибки 403, 419, 429, 500, 503, 4xx, 5xx — лёгкий шаблон `x-layouts.error` без базы и Livewire. По экрану 11 макета: кода ошибки на экране нет, всегда второй путь (каталог), тексты называют причину без «упс»; пульсация листинга — `wire:loading.delay.long` (300 мс).
- Каркас ставит класс `js` на `<html>` до отрисовки: `.js [data-collapsible]` прячет свёрнутое без мигания, утилита `requires-js` прячет то, что без скриптов бесполезно. Сворачивание, которое должно пережить перерисовку Livewire, делается на сервере.
- Шторка фильтров ниже 1280 — нативный `popover` (утилита `filter-sheet`); с 1280 тот же блок — липкая колонка 288. Листинг — 3 карточки рядом с колонкой фильтров.
- Перед сеткой листинга — скрытый заголовок `h2` «Модели»: на телефоне «Подбор» спрятан в шторку, и без него после `h1` сразу шли бы `h3` карточек. Ссылки на сером фоне (`slate`) — цветом `accent-dark`: `accent-ink` там даёт контраст 4,2.
- Фокус внутри групп с `overflow-hidden` — внутренний (`focus-visible:-outline-offset-2`).
- В листинге у товаров «Под заказ» и «Ожидается» кнопка «В корзину» по ТЗ §6.5, хотя макет рисует «Уточнить срок поставки», — см. раздел 7.

**Сервер и выкладка** (22.09.2026, ТЗ §17)
- Сервер общий с другими сайтами заказчика, панели HestiaCP на нём нет. Магазин живёт в своих контейнерах Docker (`docker/compose.yml`), системные программы сервера не меняются. Чужие сайты не трогаем.
- Выкладка — архивом закоммиченного кода по SSH: `docker/deploy.sh` собирает образ, закрывает сайт, меняет код, поднимает контейнеры и применяет миграции. Команда — в README, раздел «Сервер».
- Фото — в S3 Спринтхоста (папка `gastrosnab/` бакета `s3-968732`), база, журналы и счета — на сервере. Диски: `s3` (`MEDIA_DISK`) и `s3-private` (`INVOICES_DISK`).
- **Бакет `s3-968732` провайдер отдаёт всем целиком:** права «только владелец» на файле не мешают открыть его по прямой ссылке (проверено на сервере 22.09.2026). Поэтому счета с данными клиентов лежат на диске сервера, а не в хранилище. Диск `s3-private` умеет работать с отдельным приватным бакетом — нужны `AWS_PRIVATE_BUCKET` и `INVOICES_DISK=s3-private`.
- Приложение доверяет заголовкам `X-Forwarded-*` только из частных сетей: от этого зависит, какой адрес видит ограничение частоты форм.
- Стили собираются одинаково здесь и в образе: в `resources/css/app.css` макеты, тесты и скомпилированные шаблоны исключены из поиска классов.

**Личный кабинет** (23.09.2026)

**Заказ списком** (23.09.2026)

В сессии (`BulkOrderController::SESSION_KEY`) лежат только разобранные строки — сопоставление и цены пересчитываются при каждом показе и при «Добавить в корзину».

**Избранное** (23.09.2026)

**Корзина, заявки и лиды**
- Корзина — только через действия `AddToCart`, `ChangeCart`, `MergeGuestCart` и сверку `CartReview` (`app/Actions/Cart`, `app/Services/Cart`). Что можно купить — `CartRules::block()`; количество 1–9999 — `CartRules::quantity()`. Гостевая корзина — по токену в cookie `cart` на 30 дней (`CartStore`), не по id сессии: сессия живёт часы и меняет id при входе.
- `CartReview::review()` при каждом открытии пересчитывает цены и сохраняет новые; шапка берёт `headline()` одним запросом по ценам корзины (`App\View\CartHeadline`).
- Кнопки «В корзину», «Сравнить», формы лидов — обычные формы; `resources/js/storefront.js` отправляет их с `Accept: application/json` через общий `sendForm` и обработчики `formHandlers`; 422 — отказ с уведомлением или ошибки полей (`data-field-error`). Страница корзины (Livewire) сообщает шапке новые цифры событием `cart-updated`.
- Заявка — только `PlaceOrder` (одна транзакция: номер, позиции со снимком, журнал, очистка корзины; повтор по `idempotency_key`, в том числе удалённого заказа). Статусы — `ChangeOrderStatus` (журнал, отмена с причиной, `paid_at`), «Позвонили» — `MarkOrderCalled`, счёт — `AttachInvoice` на приватный диск `local/invoices`.
- Антиспам форм — трейт `App\Http\Requests\Concerns\GuardsAgainstBots` (поле-ловушка `website` и зашифрованная метка `started`, быстрее 3 с — отказ). Ограничения частоты: заявки — 10 в час с IP и 3 на телефон (`CheckoutController`), лиды — 10 в час с IP (`LeadController`).
- Телефон везде приводится к «+7 978 123-45-67» (`App\Support\Phone`), ИНН проверяется по контрольным цифрам (`App\Rules\Inn`). UTM-метки — middleware `RememberUtm` в сессии → в заказ и лид.
- Уведомления — слушатели `NotifyAboutNewOrder`, `TellCustomerAboutOrderStatus`, `NotifyAboutNewLead`; письма `ShouldQueue` на очереди `default`, Telegram — через `TelegramNotifier` (без токена — только в журнал). Имя и телефон в Telegram — только при `notify.telegram_include_contacts`. Письма — на рамке `x-mail.frame` в палитре сайта.
- Окна лидов — нативный `popover` (утилита `dialog-sheet`), компоненты `x-lead.dialog`, `x-lead.form`, `x-lead.request-price`; общее окно `lead-price-shared` в каркасе, товар подставляет кнопка. Ошибки лида без скриптов — в наборе `lead`, каркас показывает их уведомлением.
- Поля с условным показом без скриптов — через `group-has-[#id:checked]`; id с дефисами (см. раздел 6).

## 6. Подводные камни окружения

- **Окружение:** в каждом окне PowerShell сначала `. C:\Users\TLT-1\devtools\env.ps1`. Composer там вызывается через PHP, чтобы `^` в версиях не терялся.
- **База останавливается** при перезагрузке компьютера и после долгого простоя. Ошибка «конечный компьютер отверг запрос на подключение» — запустить `C:\Users\TLT-1\devtools\start-mariadb.ps1`.
- **Тесты** идут на MariaDB в базе `horeca_test`, SQLite запрещён. Полный прогон — около 1,5–2,5 минуты; первый прогон после перерыва медленнее.
- **Сессия в тестах сохраняется между запросами одного теста** — чтобы начать с чистой, `$this->flushSession()`.
- **`attach()` нескольких характеристик одним вызовом** со значениями в разных колонках (`value_number` и `value_string`) падает на общем INSERT — прикреплять по одной.
- **Локальная база `horeca`** содержит реальный каталог Росхолода: все категории включены, 8 корневых отмечены «На главной», у 6 заданы иконки. Характеристик, габаритов и веса в выгрузках нет — сравнение и «Проверьте перед монтажом» на реальных данных почти пустые до API. Вернуть демо-данные: `php artisan migrate:fresh --seed`.
- **Просмотр витрины:** `.claude/launch.json` — конфигурации `horeca` (порт 8000, с отладкой) и `horeca-no-debug` (порт 8010, без отладки и панели отладки — для замеров). Предпросмотр берёт собранные файлы: после новых классов Tailwind нужен `npm run build`.
- **Lighthouse:** `npx --yes lighthouse@13 <адрес> --chrome-flags="--headless=new"` с `$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'`, мерить на `horeca-no-debug`. Ошибка `EPERM` при удалении временной папки Chrome в конце — безвредна, отчёт записан.
- **Сертификаты HTTPS** для портативного PHP прописаны в `php.ini` (`devtools\php-8.4\extras\ssl\cacert.pem`); на Ubuntu это не нужно.
- **Фикстуры импорта** в windows-1251 и помечены двоичными; правка кириллицей — через `editRosholodFixture()` в `tests/Pest.php`.
- **`Http::fake()` добавляет заглушки к прежним** — подменять выгрузку между прогонами через `fakeRosholodFeeds()`.
- **Filament 5:** имя `$action` в замыканиях действий занято самим действием; опрос страницы делается на компоненте схемы (`->poll()`), а не на странице.
- **Архив дизайна** от заказчика лежит в корне (`Архив дизайна_сlaude design`) и исключён из git; распакованные макеты — в `docs/design`.
- **Панель браузера в приложении Claude обычно скрыта:** `requestAnimationFrame`, `ResizeObserver` и CSS-переходы стоят, Livewire не пишет адрес. Это не ошибки кода. Снимки — с повтором при таймауте; при эмуляции 1440 панель показывает только левый верхний угол — для обзора ставить ширину 800. Переход на страницу с ответом 404 инструмент навигации считает неудачей — переходить через `location.href` в JS.
- **Каскадные слои Tailwind 4:** правило в `@layer base` проигрывает утилитам. Правила, которые должны перебить утилиты, — вне слоёв.
- **Тесты и cookie:** тестовый клиент переносит между запросами сессию, но не cookie. Гостевая корзина живёт в cookie — в тестах её передаёт `putInCart()` из `tests/Pest.php` (`withCookie`). `staffUser()` для админки — там же.
- **Тесты и ошибки валидации:** сессия сериализуется в JSON, а тестовый клиент держит объект ошибок в памяти между запросами — следующий запрос «пересобирает» его в пустой набор. Вывод ошибок проверять открытием страницы с `withSession(['errors' => ['<набор>' => ['format' => ':message', 'messages' => [...]]]])`, как в `CheckoutTest` и `LeadsTest`.
- **Telegram в тестах:** если заданы `services.telegram.token` и `chat_id`, а очередь не подменена (`QUEUE_CONNECTION=sync`), задача реально стучится в api.telegram.org — всегда `Queue::fake()`.
- **Tailwind: подчёркивание в произвольных значениях** (`group-has-[#a_b:checked]`) читается как пробел — в таких id только дефисы.
- **PowerShell:** в строках `@"…"@` обратный апостроф — escape-символ, шаблонные строки JS `` `…${x}` `` в них ломаются тихо; JS с бэктиками править инструментом Edit или в `@'…'@`. Имя функции `R` занято псевдонимом `Invoke-History`. `Remove-Item` в командах инструмент блокирует — удалять через bash `rm`.
- **Pest-наборы данных** вычисляются до загрузки приложения: `Crypt`, фабрики и фасады в них — только внутри замыканий `fn () => …`.
- **Скрипт выкладки приходит в bash через стандартный ввод:** любая команда внутри, читающая ввод, съест остаток скрипта, и выкладка оборвётся на середине. В `docker/deploy.sh` все вызовы `docker compose` идут с `< /dev/null`.
- **`pecl.php.net` с сервера отвечает через раз.** Модуль `redis` образ берёт архивом релиза с повторами, запасной источник — GitHub.
- **Пока контейнеры перезапускаются, страницу обслуживания рисовать некому** (её рисует PHP). Поэтому nginx магазина и nginx сервера показывают статическую страницу `docker/nginx/maintenance.html` вместо ошибок 502 и 504. Простой при выкладке — около десяти секунд.
- **Контейнер `app`, пересозданный отдельно** (например, после правки `.env` и `dc up -d`), получает новый адрес в сети Docker. nginx магазина узнаёт его заново через DNS Docker (`resolver 127.0.0.11` в `docker/nginx/default.conf`); без этого сайт показывал «Обновляем сайт», пока не перезапустить `web`.
- **Конфиг сайта в nginx сервера правит certbot** (добавляет HTTPS). Перезаписывать его файлом из репозитория нельзя — потеряются настройки сертификата; менять точечно, с копией и проверкой `nginx -t`.
- **Автоматическая проверка безопасности** не даёт менять чужие сайты на сервере и расширять себе права без явного согласия заказчика в чате.
- **Очередь импорта на сервере — `IMPORTS_QUEUE_CONNECTION=redis-imports`.** По умолчанию (`database-imports`) задачи импорта и фото уходят в таблицу, которую контейнер `queue-imports` не слушает, и тихо лежат. На тестовом сайте исправлено 23.09.2026, в README записано.
- **Временные скрипты** не называть как модули стандартной библиотеки Python (`enum.py` подменил `enum` и сломал правку). В строках PowerShell после переменной не ставить двоеточие вплотную — писать `${n}:`.
