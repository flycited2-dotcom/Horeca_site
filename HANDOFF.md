### Фото поставщика до API — ждёт разрешения Росхолода

На rosholod.org фото лежат по адресу `/media/products_images/{GUID}/<файл>.jpg`, GUID совпадает с нашим `external_id`. Но имя файла неизвестно: список товаров их сайт грузит из `/api/`, закрытого для роботов в `robots.txt`; в HTML каталога — одно фото на страницу; в XML поле `СТ_АдресСсылкиURL` пустое у всех 15 017 карточек. **Без разрешения поставщика автоматический сбор не делаем.** С разрешением или архивом — команда загрузки через очередь, фото с `source = supplier` и `source_url`, чтобы API потом заменил их, а ручные остались.

## 5. Принятые решения, которые важно не сломать

**Импорт**
- Ключ товара — GUID поставщика (`products.external_id`), а не артикул: артикул пуст у 22% карточек и повторяется.
- Применение одной транзакцией; пробный прогон — та же транзакция с откатом.
- Отсутствие товара в снимке считается счётчиком `missing_runs`, а не сравнением времени; снятие — после 3 полных снимков.
- Остатки полного снимка переписываются целиком. Наличие — одним SQL-запросом; «снят с производства» он не трогает.
- Каждое поле товара заполняет один активный профиль (`OwnedFieldsGuard`).
- Импорт не пишет в поля из `locked_fields` (включая `retail_price` и `unit`), не меняет `slug`, витринные категории и ручные фото.
- Неизменившийся файл определяется ещё и по хешу (`import_runs.file_hash`); `ETag` сохраняется только после успешного прогона.
- Существующие склад и бренд с тем же названием связываются, а не создаются заново.

**Каталог и админка**
- Ручные правки — только через `SaveProductByManager` (замки, строка поиска, счётчики категорий, кэш). «Вернуть значение поставщика» снимает замок и обнуляет `source_hash`.
- Товары вручную не создаются; удаляет их мягко только администратор. Категории и бренды удаляет администратор. Импорт запускает менеджер, настройки профиля и поставщика — администратор.
- Кэш каталога сбрасывают `CatalogCacheObserver` (категории, бренды, склады) и действия менеджера; товары наблюдателем не охвачены сознательно. В кэше: навигация (`navigation`), плитки главной (`home`), список брендов (`brands`).
- Смена `slug` ставит 301 без цепочек; новая страница освобождает свой адрес от старого редиректа.
- **Слушатели событий** из `app/Listeners` Laravel находит сам. В `AppServiceProvider` их не регистрировать — иначе они вызываются дважды.

**Витрина**
- На витрине только видимые, не снятые товары из включённых категорий (`CatalogQuery::listed`); выключенная категория скрывает свою ветку. После первого импорта витрина пуста, пока менеджер не включит категории.
- Все выборки витрины — через `CatalogQuery` и `ProductSearch`; цены — через `PriceResolver::forMany` в контроллере или компоненте, шаблоны только показывают.
- Дизайн — из макетов `docs/design`; токены только в `@theme` файла `resources/css/app.css`; разметка собирается из компонентов, между страницами не копируется. Новый компонент добавляется и в стайлгайд.
- Витрина работает без JS обычными ссылками и формами; Livewire и `resources/js/storefront.js` — улучшение поверх.
- Деньги — только целые копейки (`Money`), проценты — базисные пункты (`Percent`); цены выводятся через `Typography::money` с неразрывными пробелами.
- Контейнер — утилита `container-page`: до 1296 px контента, поля 12 · 24 · 32 · 56. Липкие колонки — `top-21` (шапка 68 + 16).
- Каркас получает данные только через `StorefrontLayoutComposer` → `$shell` (`App\View\StorefrontShell`): настройки одним запросом, корневые разделы из кэша каталога, число моделей в сравнении. Ссылки на служебные страницы — только на включённые.
- **Листинги** (`CategoryListing`, `SearchListing`, `BrandListing`) делят состояние через трейты: `FiltersListing` (фильтры, сортировка, страницы в адресе), `RefinesBySection` (раздел `category=` для поиска и бренда), `ChoosesView` (плитка/список в cookie). Общая разметка — компоненты `filter-panel`, `filter-bar`, `filter-chips`, `product-grid`, `section-links`, `pagination`, `empty-results`. Имена полей в адресе совпадают с GET-формой: `price_from`, `price_to`, `in_stock`, `brand[]`, `sort`, `page`, `view`, `q`, `category`.
- **Поиск:** `ProductSearch::scope()` делает `LIKE` по `search_text` один раз и отдаёт id; счётчики и фасеты считаются по этим id. Точное совпадение сравнивает сжатые `sku`, `supplier_code` и `model`, а не `search_text` (иначе артикул в названии другого товара дал бы ложное совпадение).
- **Карточка товара:** строки фактов — `App\View\ProductFacts` (типографика данных §9); вкладки с 768 px и аккордеоны ниже — одна разметка, неактивный раздел помечен `data-inactive`, прячет его CSS вне слоёв; без скриптов разделы идут подряд.
- **Сравнение:** `CompareList` — гость в сессии, клиент в `compare_items`, при входе списки объединяются (`MergeGuestComparison`), не больше 4. Кнопка `x-compare.toggle` рисует обе формы (добавить и убрать — один адрес, разные методы), скрипт отправляет форму с `Accept: application/json` и переключает `hidden`. Таблица — `App\View\ComparisonTable`: «Критично для монтажа» (габариты, масса, главные характеристики) первым блоком, совпадающие строки — сноской.
- **Уведомления** об итоге действия — `x-ui.notice`: без скриптов из сессии (`notice` = `text`, `href`, `link`), со скриптами — из `<template data-notice-template>` каркаса.
- **Адреса без маршрута:** любая 404 сначала спрашивает `redirects` (`FollowRedirect` в `bootstrap/app.php`), затем `Route::fallback` открывает включённую страницу по slug, затем 404 в каркасе витрины. Текст страниц — Markdown через `App\View\RichText` (HTML вырезается). Ошибки 403, 419, 429, 500, 503, 4xx, 5xx — лёгкий шаблон `x-layouts.error` без базы и Livewire. По экрану 11 макета: кода ошибки на экране нет, всегда второй путь (каталог), тексты называют причину без «упс»; пульсация листинга — `wire:loading.delay.long` (300 мс).
- Каркас ставит класс `js` на `<html>` до отрисовки: `.js [data-collapsible]` прячет свёрнутое без мигания, утилита `requires-js` прячет то, что без скриптов бесполезно. Сворачивание, которое должно пережить перерисовку Livewire, делается на сервере.
- Шторка фильтров ниже 1280 — нативный `popover` (утилита `filter-sheet`); с 1280 тот же блок — липкая колонка 288. Листинг — 3 карточки рядом с колонкой фильтров.
- Перед сеткой листинга — скрытый заголовок `h2` «Модели»: на телефоне «Подбор» спрятан в шторку, и без него после `h1` сразу шли бы `h3` карточек. Ссылки на сером фоне (`slate`) — цветом `accent-dark`: `accent-ink` там даёт контраст 4,2.
- Фокус внутри групп с `overflow-hidden` — внутренний (`focus-visible:-outline-offset-2`).
- В листинге у товаров «Под заказ» и «Ожидается» кнопка «В корзину» по ТЗ §6.5, хотя макет рисует «Уточнить срок поставки», — см. раздел 7.

- **`attach()` нескольких характеристик одним вызовом** со значениями в разных колонках (`value_number` и `value_string`) падает на общем INSERT — прикреплять по одной.
- **Локальная база `horeca`** содержит реальный каталог Росхолода: все категории включены, 8 корневых отмечены «На главной», у 6 заданы иконки. Характеристик, габаритов и веса в выгрузках нет — сравнение и «Проверьте перед монтажом» на реальных данных почти пустые до API. Вернуть демо-данные: `php artisan migrate:fresh --seed`.
- **Просмотр витрины:** `.claude/launch.json` — конфигурации `horeca` (порт 8000, с отладкой) и `horeca-no-debug` (порт 8010, без отладки и панели отладки — для замеров). Предпросмотр берёт собранные файлы: после новых классов Tailwind нужен `npm run build`.
- **Lighthouse:** `npx --yes lighthouse@13 <адрес> --chrome-flags="--headless=new"` с `$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'`, мерить на `horeca-no-debug`. Ошибка `EPERM` при удалении временной папки Chrome в конце — безвредна, отчёт записан.
- **Сертификаты HTTPS** для портативного PHP прописаны в `php.ini` (`devtools\php-8.4\extras\ssl\cacert.pem`); на Ubuntu это не нужно.
- **Фикстуры импорта** в windows-1251 и помечены двоичными; правка кириллицей — через `editRosholodFixture()` в `tests/Pest.php`.
- **`Http::fake()` добавляет заглушки к прежним** — подменять выгрузку между прогонами через `fakeRosholodFeeds()`.
- **Filament 5:** имя `$action` в замыканиях действий занято самим действием; опрос страницы делается на компоненте схемы (`->poll()`), а не на странице.
- **Архив дизайна** от заказчика лежит в корне (`Архив дизайна_сlaude design`) и исключён из git; распакованные макеты — в `docs/design`.
- **Панель браузера в приложении Claude обычно скрыта:** `requestAnimationFrame`, `ResizeObserver` и CSS-переходы стоят, Livewire не пишет адрес. Это не ошибки кода. Снимки — с повтором при таймауте; при эмуляции 1440 панель показывает только левый верхний угол — для обзора ставить ширину 800. Переход на страницу с ответом 404 инструмент навигации считает неудачей — переходить через `location.href` в JS.
- **Каскадные слои Tailwind 4:** правило в `@layer base` проигрывает утилитам. Правила, которые должны перебить утилиты, — вне слоёв.
- **Временные скрипты** не называть как модули стандартной библиотеки Python (`enum.py` подменил `enum` и сломал правку). В строках PowerShell после переменной не ставить двоеточие вплотную — писать `${n}:`.

## 7. Что ждём от заказчика

1. **Название магазина и логотип** — сейчас в шапке «HoReCa Shop» из `APP_NAME`.
2. **Разрешение Росхолода на фото до API** (письмо менеджеру) — см. раздел 4.
3. **Ответ Росхолода:** можно ли продавать ниже РРЦ и какие оптовые скидки допустимы — до ответа оптовые цены равны розничным.
4. **Реквизиты продавца, режим НДС, адрес самовывоза, телефоны, режим работы** — заполняются в настройках, выводятся в шапке, футере и разметке `Organization`.
5. **Тексты страниц** «Доставка», «Оплата», «Гарантия», «Оптовикам», «О компании», «Контакты» и юридических страниц — пока страницы выключены и в меню не видны.
6. **Бот Telegram и `chat_id`** группы менеджеров — без них уведомления пишутся только в журнал.
7. **Домен и SSH-доступ** к VPS — для стейджинга и прода.
8. **Решение о слиянии веток** спринтов в `main`.
9. **Кнопка у «Под заказ» в листинге:** по ТЗ — «В корзину» (так сделано: это 88 % каталога), в макете — «Уточнить срок поставки». Оставить как в ТЗ?
10. **Подпись к «Цене по запросу»:** сейчас «Менеджер пришлёт цену и срок поставки»; в макете — «Ответим со счётом в течение рабочего дня». Это обещание срока — подтвердить, если так и будет.
11. **Оговорка в футере** «Цены на сайте не являются публичной офертой» взята из макета — подтвердить у юриста.
12. **«Выгрузить XLSX» на странице сравнения** есть в макете, но не в ТЗ — нужна ли?
