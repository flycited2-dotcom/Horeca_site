# API Росхолода: ответ поставщика

**Дата ответа:** 17.09.2026
**На что отвечает:** вопросы, отправленные 16.09.2026 (ТЗ §20, вопросы поставщику по API).

Схема API ещё согласовывается. Всё ниже — намерения поставщика, а не контракт: окончательные поля, лимиты и частота обновления появятся в документации.

## Что ответил поставщик

| Вопрос | Ответ |
|---|---|
| GUID товара | Основной идентификатор товара в API — GUID из 1С. По нему связываются товар, цены, остатки и изображения. Совпадает ли он с полем `ID` одновременно в `Catalog.xml` и `OstatkiYandex.xml`, поставщик перепроверит на текущей выгрузке. |
| Пример ответа | Конкретного примера пока нет: состав полей ещё меняется, результаты обещаны «в ближайшее время». Ориентировочный состав: GUID, наименование, код, артикул, бренд, вид номенклатуры, страна производства, характеристики, изображения, РРЦ, числовые остатки по складам. |
| Документация и доступ | Документация готовится в OpenAPI/Swagger, отдельно будет описан регламент интеграции и обновления данных. Доступ дилера — персональный API-ключ или токен в заголовке авторизации. Лимиты запросов будут указаны в документации. Сроков не назвали. |
| Изменения с даты и вебхуки | В первой версии упор на стабильное получение каталога, цен и остатков. Выборку изменений (`updated_since`) и вебхуки рассматривают отдельно, конкретный вариант не обещают. Частота обновления цен и остатков будет в регламенте. |
| Цены | В первой версии передаётся РРЦ, **цена сразу с НДС**. Индивидуальные дилерские цены прорабатывают. Можно ли продавать ниже РРЦ, в том числе оптом, поставщик предложил уточнить у менеджера Росхолода: это условия работы с дилерами. |
| Фото | URL, связанные с GUID товара; у товара может быть несколько фото. Размеры исходников разные, к фиксированному разрешению привязываться не стоит. Формат и постоянное хранение копий на нашей стороне — без ограничений. |
| Характеристики | JSON в читаемом виде, например `"Ширина": "400 мм"`. На первом этапе значение и единица измерения могут идти одной строкой. Про единый справочник ключей ответа нет. |
| Снятые с производства | Вопрос прорабатывается. Поставщик согласен, что товар не должен просто исчезать из выгрузки: интеграция должна понимать, что он снят с производства. |
| Остатки | Числами в разрезе складов: видно и наличие, и количество на конкретном складе. |
| «В пути» и дата поступления | В базовую версию API не входят, прорабатываются. |
| Совместимость | После фиксации схемы поставщик постарается не менять существующие поля без необходимости. |

## Что это значит для проекта

- **Ключ товара не меняется.** XML-импорт и будущий API-адаптер сопоставляют товары по GUID. Пока поставщик не подтвердил совпадение с `ID` в XML, перед переключением на API обязателен пробный прогон с отчётом о совпадении (§18, спринт 7).
- **РРЦ включает НДС.** Она хранится как есть в `rrp_price`; подпись о НДС на витрине берётся из `seller.vat_mode`. Можно ли продавать ниже РРЦ, заказчик узнаёт у менеджера Росхолода. До ответа оптовые скидки выключены (§7).
- **Фото любого размера подходят.** Конверсии medialibrary вписывают изображение в 160, 600 и 1200 пикселей без увеличения (§5.2).
- **Характеристики разбираем сами.** Строку «400 мм» на число и единицу делит `AttributeValueParser`; он должен понимать значение и с пробелом, и без.
- **Снятые с производства.** Пока у поставщика нет признака, работает наш механизм: товар снимается после 3 полных снимков без него (§6.3). Когда признак появится, API-адаптер будет ставить `discontinued` сразу.
- **«Ожидается» не заполняется.** Статус `incoming` остаётся в модели (§6.5), но ни XML, ни API первой версии данных для него не дают.
- **Категории — под вопросом.** В ориентировочном составе полей нет дерева категорий, есть только «вид номенклатуры». Если дерева в API не будет, `Catalog.xml` останется источником дерева и привязки товаров к категориям.
- **Полные снимки.** Первая версия API, как и XML, — полная выгрузка каталога и остатков; инкрементальные обновления не закладываем. Расписание API-профиля задаётся по регламенту и лимитам.
- **Спринт 7 не начинается** до выхода документации и тестового доступа.

## Что осталось открытым

1. Совпадает ли GUID в API с `ID` в `Catalog.xml` и `OstatkiYandex.xml` — поставщик перепроверит.
2. Документация, тестовый доступ, лимиты и регламент обновления — сроков нет.
3. Признак снятия с производства — прорабатывается.
4. Будет ли в API дерево категорий с GUID или только «вид номенклатуры».
5. Есть ли единый справочник ключей характеристик.
6. Можно ли продавать ниже РРЦ и какие оптовые скидки допустимы — вопрос заказчика к менеджеру Росхолода.
