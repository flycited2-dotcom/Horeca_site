# API Росхолода: ответ поставщика на вопросы по Dealer API

**Дата ответа:** 02.10.2026 (ночью).
**На что отвечает:** вопросы к API после документации от 01.10.2026 (`docs/supplier-api-2026-09-17.md` — прежний ответ).
**Документация:** https://api.rosholod.org/docs, спецификация — https://api.rosholod.org/openapi.json (открыты без токена, версия 1.1.0, на русском, с примерами).
**Токен:** поставщик выдал отдельный токен на 14 дней, только чтение. В репозитории и документах его нет: заказчик вводит его на сервере скриптом `docker/set-rosholod.sh`.

## Что ответил поставщик

| Вопрос | Ответ |
|---|---|
| Загрузка каталога | Добавили курсорную пагинацию (`next_cursor`): весь каталог без предела `offset` ≤ 10 000. Фильтра `updated_after` **нет**: цены и остатки — только полным обходом, потребность в изменениях учтена «для дальнейшей доработки». |
| Лимиты | 5 запросов в секунду на токен (до 300 в минуту). На 429 — ждать по заголовку `Retry-After`. |
| Структура каталога | В справочник видов номенклатуры добавлен `parent_id` для дерева. Соответствие структуре XML поставщик предлагает сверить на контрольной выборке. Фильтр товаров по виду дочерние виды не включает. |
| Идентификаторы | `id` — идентификатор внутри API; `source_id` — исходный идентификатор из учётной системы (формат UUID не гарантируется, может быть `null`). В запросах к API — только `id`. |
| Дилерские цены | Сейчас только розничная цена. Индивидуальных дилерских цен и скидок нет. |
| Сроки поставки | `production_time` и `order_option` — текст из учётной системы. Отдельного поля с датой ожидаемой поставки нет. |
| Характеристики | В `attributes` полной карточки: «название: значение», типы значений разные, единицы — в названии ключа («Ширина, мм»). Набора ключей и поля гарантии нет, всё зависит от заполнения карточки. |
| Фото | Можно скачивать и хранить у себя; при замене изображения ссылка меняется, поэтому брать актуальный список `images`. Ограничивать число одновременных скачиваний. |
| Исчезнувшие товары | Статуса снятия с производства и списка удалений нет: только сверка по полному обходу. |
| Тестовая среда | Отдельной нет; токен на 14 дней, только чтение. |

## Маршруты (`/api/v1/dealer/*`, `Authorization: Bearer <токен>`)

| Маршрут | Право | Что отдаёт |
|---|---|---|
| `GET /products` | `catalog:read` | Краткие карточки: `id`, `source_id`, `name`, `code`, `article`, `brand_id`, `product_type_id`, `country_id`, `promo`, `images[]` (`id`, `url` WebP, `is_default`, `width`, `height`). До 100 на страницу. |
| `GET /products/export` | `catalog:read` | Полные карточки: то же и `description`, `brand`, `product_type`, `country`, `vat`, `production_time`, `order_option`, `is_featured`, `attributes`. **До 20 на страницу.** |
| `GET /products/{id}` | `catalog:read` | Одна полная карточка. |
| `GET /brands`, `/product-types`, `/countries` | `catalog:read` | Справочники `{id, name}`; у видов ещё `parent_id`. |
| `GET /warehouses` | `catalog:read` | `id`, `name`, `city`, `address`, `work_time`. |
| `GET /prices` | `prices:read` | `product_id`, `price` (строка «1234.56», РРЦ), `last_received_at`. Отсутствие строки не 0. |
| `GET /stocks` | `stocks:read` | `product_id`, `warehouse_id`, `available` (целое), `last_received_at`. Нулевые строки публикуются, отсутствие строки не 0. |

Все списки: `limit`, `offset` ≤ 10 000, `cursor`; ответ `{items, limit, offset, has_more, next_cursor}`. Ответы 401, 403, 422, 429 (`Retry-After`), 503; у карточки ещё 404.

## Что это значит для проекта

- **Содержимое — на API.** Описание, характеристики, страна и фото приходят одной выгрузкой `/products/export` (около 750 запросов для 15 тыс. товаров, 3–4 минуты при 4 запросах в секунду) вместо ночной загрузки с сайта (1 ч 16 мин, страница за страницей). Единицы характеристик в ключе — как у нас в `AttributeValueParser`. Реализовано: `RosholodApiContentSource`, переключатель `SUPPLIER_CONTENT_SOURCE=site|api`.
- **Остатки и цены остаются в XML**, пока API не отдаст дату поступления и изменения с даты: «Ожидается <дата>» (§8.3) берётся только из XML, а полный обход `/stocks` и `/prices` каждые 30 минут — сотни запросов ради данных, которые уже есть. Числовые остатки по складам на витрине не показываются. Вернуться к вопросу, когда у API появится `updated_after` и дата поступления.
- **Ключ товара.** Скорее всего `source_id` = GUID из XML (наш `external_id`); проверяет `supplier:api-check` на токене. До проверки по умолчанию `ROSHOLOD_API_EXTERNAL_ID=source_id`.
- **Виды номенклатуры с `parent_id`** дают второе дерево категорий; XML-каталог остаётся источником структуры, пока сверка на выборке не покажет совпадения (`supplier:api-check` печатает число совпавших по названию).
- **Снятие с производства** — по-прежнему по пропаже из полного снимка XML (§6.3, шаг 7); API этого не заменяет.
- **Дилерские цены и скидки** — нет, оптовые цены остаются на пределе скидки 0 (§7) до ответа Росхолода.
