# 20. Что нужно от заказчика

**Блокеры дизайна и запуска**
1. **Название магазина** — «Гастроснаб» (решено 22.09.2026). **Открыто:** логотип; пока в шапке — название текстом.
2. **Референсы для дизайна:** 3–5 сайтов, которые нравятся, и 2–3 прямых конкурента, у каждого — что именно нравится. Заказчик пришлёт позже вместе с материалами для Claude Design.
3. **Домен и сервер** — решено 22.09.2026: `gastrosnab.ru` главный, `гастроснаб.рф` перенаправляет на него; VPS Спринтбокса `212.116.115.150`, доступ по SSH-ключу. HestiaCP на сервере нет, магазин — в Docker (§17.1). Файлы — в S3 Спринтхоста (§17.9). **Открыто:** где хранить внешнюю копию бэкапа (§17.5).
4. **Реквизиты продавца, режим НДС** (цены с НДС или без), адрес самовывоза, график, телефоны, e-mail.
5. **Telegram:** бот через @BotFather и `chat_id` рабочей группы менеджеров.
6. **Юрист по 152-ФЗ:** согласие, политика, уведомление Роскомнадзора, cookie и Метрика, контакты клиентов в Telegram.
7. **Локальная среда разработки** — решено 16.09.2026: Windows, портативные инструменты (§17.0).

**Цены**
8. Цена в XML и в API первой версии — РРЦ с НДС (подтверждено заказчиком 16.09.2026 и поставщиком 17.09.2026). **Открыто:** обязательна ли РРЦ к соблюдению и можно ли продавать ниже неё, в том числе оптовикам. Поставщик переадресовал вопрос к менеджеру Росхолода, так как это условия дилерства; узнаёт заказчик.
9. `pricing.max_discount_without_purchase` и `pricing.min_margin_percent`.
10. Ценовые группы и скидки. Стартовые: Розница 0%, Опт-1 10%, Опт-2 15%, Сеть 20% — подтвердить.

**Вопросы поставщику по API** — отправлены 16.09.2026, ответ получен 17.09.2026. Подробно — `docs/supplier-api-2026-09-17.md`.
11. GUID товара. Основной ключ API — GUID из 1С, по нему связаны товар, цены, остатки и фото. **Открыто:** совпадение с `ID` в `Catalog.xml` и `OstatkiYandex.xml` поставщик перепроверит.
12. Пример ответа API. **Ждём:** состав полей ещё согласовывается. Ориентировочно: GUID, наименование, код, артикул, бренд, вид номенклатуры, страна, характеристики, фото, РРЦ, числовые остатки по складам.
13. Документация и доступ. Готовится OpenAPI/Swagger и регламент интеграции; авторизация — персональный токен дилера в заголовке; лимиты будут в документации. **Ждём:** сроков нет.
14. Изменения с даты и вебхуки. **Закрыто:** в первой версии их нет, закладываем полные снимки; частота обновления — в регламенте.
15. Фото. **Закрыто:** несколько URL на товар, размеры разные, формат и хранение копий у себя — без ограничений.
16. Характеристики. **Частично:** значение и единица идут одной строкой («Ширина»: «400 мм»); про единый справочник ключей ответа нет.
17. Снятые с производства и «в пути». **Открыто:** признак снятия прорабатывается; «в пути» с датой поступления в базовую версию не входит.
18. Дерево категорий в API. **Открыто:** в ориентировочном составе полей есть только «вид номенклатуры». Если дерева не будет, `Catalog.xml` остаётся источником категорий.

**Контент и логистика**
19. Сроки доставки со складов поставщика до Симферополя по складам; порог бесплатной доставки по городу.
20. Тексты: «Почему мы» (только подтверждённые факты), выгоды для оптовиков, обещание по времени перезвона, обязательные страницы.
21. Состав подборок «Кафе до 50 посадок», «Бар», «Кондитерский цех» — или поручение менеджеру после импорта.

**Подтверждено заказчиком 16.09.2026** — решения по умолчанию остаются:
- оптовые скидки не действуют, пока не задан предел (`pricing.max_discount_without_purchase = 0`);
- название ценовой группы клиенту не показывается (`pricing.show_tier_name = false`);
- в Telegram не передаются имя и телефон клиента (`notify.telegram_include_contacts = false`);
- Яндекс.Метрика загружается после согласия на cookie;
- снятые с производства товары не выводятся в листингах и поиске, но открываются по прямой ссылке.
