Спецификация для разработки

Свод правил к макету «Карточка товара.dc.html» (13 экранов). Всё, что здесь описано, взято из макета: токены, сетка, поведение на четырёх точках перелома и правила, по которым компоненты перестраиваются. Ничего нового не вводится — при расхождении макет главнее текста.

1. Точки перелома

Диапазон Контейнер Что меняется
≥ 1280 1320 / поля 56 Базовый макет. Листинг 4 карточки в ряд (288 + gap 24). Фильтры — левая колонка 264 px, липкая. Карточка товара: галерея 560 + описание + правая панель покупки 320, панель липкая. Кабинет: таблица заказов в шесть колонок.
1024–1279 fluid / поля 32 Листинг 3 в ряд. Панель покупки уходит под галерею во всю ширину и остаётся липкой снизу (высота 72). Фильтры сворачиваются в кнопку «Фильтры · N» с выезжающей панелью. В таблице заказов колонка «Состав» усекается до одной строки.
768–1023 fluid / поля 24 Экран 10 в макете. Листинг 2 в ряд. Верхняя полоса теряет каталог-меню, остаются поиск, счета, корзина. Сравнение переходит в горизонтальный скролл с закреплённой колонкой параметров (180).
< 768 390 / поля 12 Экран 14 в макете. Одна колонка везде. Шапка 56: бургер, логотип, корзина; поиск строкой под ней. Карточки листинга горизонтальные: заглушка 96×96 слева, текст справа. Фильтры — шторка поверх листинга с кнопкой «Показать N моделей» внизу. Карточка товара: галерея 200, разделы аккордеонами, покупка в липкой панели снизу (цена + счётчик + кнопка). Корзина: строка в две строки, итог липкий. Таблицы кабинета — карточки «ключ → значение», оба статуса рядом в две колонки.

Перелом задаётся по контейнеру, а не по устройству. Кнопки и поля сохраняют высоту 44 px на всех диапазонах, включая десктоп: заказ часто оформляют с планшета на кухне.

4. Компоненты: что реализуем

Компонент Состояния и поведение
КнопкаЧетыре вида: основная (#0072B0, белый текст), вторичная (рамка #0098EA, hover-фон #E5F5FD), нейтральная (рамка #D3D9DE, hover-рамка #0072B0), недоступная (#F4F6F7 / #8A959E, aria-disabled). Высота 44 на всех диапазонах.
Карточка товараЗаглушка 1b — пиктограмма типа оборудования (steel-400 на #F4F6F7), не пустой прямоугольник. Порядок: бренд + артикул, название, две ключевые характеристики моно, цена, статус, кнопка. Skeleton — те же блоки с анимацией om-pulse.
Счётчик44×44 кнопки, поле 52. Значение редактируемое, при потере фокуса нормализуется; 0 удаляет строку с возможностью отмены.
Строка поискаНормализация запроса: пробелы, дефисы и регистр в артикуле игнорируются. Пустая выдача предлагает исправленные варианты, а не «ничего не найдено».
СравнениеПо умолчанию только различия; переключатель раскрывает совпадающие 20+ строк. Колонка параметров закреплена при горизонтальном скролле.
Заказ в кабинетеДве независимые колонки статуса: оплата и отгрузка. Заказ может быть оплачен и не отгружен — одним бейджем не схлопывать.
Вход и регистрацияФорма входа 420: почта или телефон, пароль, «Войти по SMS». Ошибка — рамка #C2410C, текст #A3350B под полем, со счётчиком попыток. Регистрация начинается с ИНН: реквизиты (наименование, КПП, ОГРН, адрес) подставляются, вручную правятся по ссылке. Три шага: организация → контактное лицо → доступ. После отправки — экран «Заявка на проверке»: каталог и сроки открыты, скрыты только цены.
Цена дилераТри состояния: гость (базовая цена + приглашение войти), дилер (базовая зачёркнута, «Ваша цена» крупно, бейдж уровня и прогресс до следующего), без цены («Цена по запросу» + срок ответа). Процент скидки без строки «почему столько» не показывать.
Лимит отсрочкиВ корзине — полоса «использовано / лимит» и остаток после этого заказа. Не хватает лимита: способ «Отсрочка» становится недоступным с указанием нехватки в рублях, появляется частичная отсрочка и «Запросить увеличение лимита». Просрочка: отсрочка приостановлена, но каталог, цены и заказы по счёту работают — блокируется способ оплаты, а не работа.
Загрузка / ошибкаom-pulse для скелетов, om-spin для спиннера. Ошибка всегда с действием: повторить, позвонить менеджеру, оставить заявку. Ни одно состояние не показывает пустой экран без текста.

5. Правила контента

  • Срок и наличие — конкретны: «Ожидается 28 сентября», не «скоро».
  • Цена без цены не прячется: «Цена по запросу» плюс что произойдёт дальше.
  • Нет фото — заглушка с типом оборудования.
  • Скидка показывается как «Ваша цена», а не как процент со звёздочкой.
  • Никаких рейтингов, отзывов и таймеров: данных нет, доверие строится на сроках и документах.
  • Суммы в счёте: НДС 20 % выделяется отдельной строкой, итог — прописью в PDF.

6. Доступность

  • Контраст текста ≥ 4,5:1, крупных заголовков ≥ 3:1 — проверено по всем экранам.
  • Фокус виден всегда: outline 2px #0098EA с offset 2, скрывать нельзя.
  • Цель нажатия ≥ 44×44 на всех диапазонах.
  • Статус наличия дублируется текстом, не только цветом.
  • Таблицы заказов и сравнения — настоящие table с thead и scope, не div-сетки.
Открытые вопросы к команде
  • Источник фотографий товаров: пока везде заглушки по типу оборудования.
  • Правила расчёта персональной цены дилера — нужен алгоритм со стороны бэка.
  • Лимит отсрочки и его блокировка при превышении: показывать ли прогноз в корзине.
  • Мобильная версия < 768 описана правилами, но не отрисована — нужен отдельный проход, если она в первом релизе.
