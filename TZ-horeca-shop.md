## Что изменилось

### Версия 1.12 — 22.09.2026

Сервер, домены и хранение файлов — после осмотра сервера, решения заказчика:
- §17.1: на VPS Спринтбокса `212.116.115.150` нет HestiaCP, PHP 8.4, MariaDB, системного Redis и Supervisor, а поставить HestiaCP можно только на чистый сервер. Сервер общий с другими сайтами заказчика. Магазин работает в своих контейнерах Docker (PHP-FPM, nginx, MariaDB 11.8, Redis 7, две очереди, планировщик) и системные программы сервера не меняет. Supervisor заменён контейнерами очередей, cron — контейнером `scheduler` (§17.4, §17.5).
- §17.2, §20: домены — `gastrosnab.ru` (главный) и `гастроснаб.рф` с 301 на него. Тестовый сайт — `test.gastrosnab.ru`, закрыт от поисковиков. Название магазина — «Гастроснаб».
- §17.9, §3: фото товаров и счета лежат в S3-хранилище Спринтхоста (бакет `s3-968732`, папка `gastrosnab/`): диск сервера почти заполнен. Новая библиотека `league/flysystem-aws-s3-v3`, из AWS SDK оставлен только S3. База остаётся на сервере.
- §17.5, §17.9: бэкапы в бакет S3 не кладутся — решение заказчика. Место внешней копии выбирается к спринту 8.
- §17.6: почта HestiaCP недоступна. Отправитель — `shop@gastrosnab.ru` через Postfix сервера или почтовый сервис в РФ, выбор в спринте 8.
- §17.7: выкладка — архив закоммиченного кода по SSH и `docker/deploy.sh`, вместо `git pull` на сервере.
- §15.11: заголовки безопасности отдаёт nginx контейнера. Адрес покупателя приложение берёт из `X-Forwarded-For`, но только от прокси из частных сетей: от него зависят ограничения частоты форм.

### Версия 1.11 — 22.09.2026

Уточнения по корзине и оформлению (спринт 4):
- §10.1: гостевая корзина находится по собственному токену в cookie на 30 дней (его и хранит `carts.session_id`): сессия сайта живёт часы, корзина гостя — 30 дней. При входе корзина сливается с корзиной клиента по его ценам, что купить уже нельзя — не переносится. Просроченные гостевые корзины удаляются по расписанию.
- §10.1: количество 0 в корзине удаляет позицию с «Вернуть», как счётчик в макете; «Вернуть» кладёт товар заново по текущей цене.
- §10.1, §7: подпись о НДС — только текстом из `seller.vat_mode` («Цены с НДС» / «НДС не облагается»), сумма НДС не считается: ставки в настройках нет.
- §10.2: ИНН проверяется по контрольным цифрам; телефон в любом виде приводится к «+7 978 123-45-67». Кнопка «Отправить заявку» активна всегда, как в §10.2, хотя макет выключает её при ошибке.
- §10.3: в заказе `subtotal` — сумма по розничным ценам, `discount` — разница с ценами клиента, `total` — к оплате. UTM-метки перехода запоминаются в сессии и попадают в заказ.
- Экраны 6 и 12 макета шире MVP: шаблоны закупки, спецификация XLSX, раздельные отгрузки, «Получить счёт» в один шаг и подстановка реквизитов по ИНН — после запуска (§21).
- §5, §12: у `orders` добавлено `deleted_at` — §12 требует мягкого удаления заказов администратором, в схеме поля не было. Повтор формы с ключом удалённого заказа новый заказ не создаёт.
- §12: смена статуса заказа — любой переход с записью в журнал (автор, комментарий); жёсткой схемы переходов ТЗ не задаёт. «Позвонили» переводит новую заявку в работу и закрепляет за менеджером.
- §6.5, §8: окна коротких заявок — нативный `popover`: открываются и отправляются без скриптов, со скриптами — без перезагрузки. «Запросить цену» в листингах — одно окно на страницу, товар подставляет кнопка; без скриптов товар можно назвать в сообщении. Ссылка у товара «Под заказ» — «Узнать срок», как в §6.5.
